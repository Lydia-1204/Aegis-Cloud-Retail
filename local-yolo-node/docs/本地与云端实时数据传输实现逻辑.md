# 本地与云端实时数据传输实现逻辑

本文档说明本地 YOLO 客流识别项目如何通过网络把结构化客流数据发送到已部署在云端的 Aegis 后端，并由云端后端继续推送到前端展示、入库和同步到 Go 业务服务。

核心原则：本地 YOLO 不上传视频流，只上传轻量 JSON 数据。

## 1. 总体链路

完整链路如下：

```text
本地摄像头/视频流
  -> 本地 YOLO + ByteTrack 识别与计数
  -> HTTP JSON 上报到云端 traffic-sense
  -> WebSocket 推送到前端实时客流页面
  -> Python 库 ai_customer 持久化历史客流
  -> gRPC 同步到 Go store-ops
  -> Go 库 customer_logs 进入经营分析数据源
```

其中 Aegis 现有后端已经提供三类接口：

| 数据方向 | 接口 | 用途 |
| --- | --- | --- |
| YOLO -> 云端 | `POST /edge/traffic/snapshot` | 上报当前画面人数，用于前端实时刷新 |
| YOLO -> 云端 | `POST /edge/traffic/history-batch` | 上报一个统计窗口内的进店/出店人数，用于入库和经营分析 |
| 前端 -> 云端 | `WS /api/ai/traffic/realtime/{store_id}?token=<JWT>` | 前端订阅某个门店的实时客流推送 |

当前前端只展示 `current_people_count`。`customer_enter_total` 和 `customer_leave_total` 先用于历史入库、Go 侧同步和后续分析；如果后续要在页面上实时显示进店/出店累计数，需要扩展 WebSocket payload 和前端页面。

## 2. 云端访问方式

### 2.1 临时联调方式

如果云服务器安全组、防火墙和 Docker 端口映射已经开放 `8083`，本地 YOLO 可以直接请求 `traffic-sense`：

```text
http://<云服务器IP>:8083/edge/traffic/snapshot
http://<云服务器IP>:8083/edge/traffic/history-batch
```

这种方式最适合快速联调，但不建议长期用于生产，因为它直接暴露了 Python 微服务端口。

### 2.2 正式推荐方式

正式部署建议只对外暴露 Nginx 的 `80/443`，由 Nginx 或 Gateway 转发边缘节点接口：

```text
http://<域名或云服务器IP>/edge/traffic/snapshot
http://<域名或云服务器IP>/edge/traffic/history-batch
```

需要注意：当前生产 `deploy/nginx.conf` 已经把 `/api/` 转发到 `gateway:8080`，前端 WebSocket 订阅可走 `/api/ai/traffic/realtime/...`；但 `/edge/traffic/*` 还需要额外放行或转发。

可选做法有两种：

1. Nginx 直接把 `/edge/traffic/` 转发到 `traffic-sense:8083`。
2. Nginx 把 `/edge/traffic/` 转发到 Gateway，再在 `integration_gateway.py` 里增加 `/edge/traffic -> TRAFFIC_SENSE_BASE` 路由。

推荐第二种，因为所有外部入口都经过统一 Gateway，后续更方便加鉴权、日志和限流。

## 3. 接口数据格式

### 3.1 实时快照接口

接口：

```text
POST /edge/traffic/snapshot
Content-Type: application/json
```

请求体：

```json
{
  "store_id": 1,
  "current_people_count": 14,
  "timestamp": 1779120000000
}
```

字段说明：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `store_id` | number | 门店 ID，必须与 Aegis 门店表一致 |
| `current_people_count` | number | 当前画面人数，不能小于 0 |
| `timestamp` | number | 本地毫秒级时间戳 |

成功响应：

```json
{
  "code": 0,
  "message": "success",
  "data": null
}
```

云端收到后会更新该门店的实时人数，并向已连接的前端 WebSocket 推送：

```json
{
  "event": "TRAFFIC_TICK",
  "store_id": 1,
  "data": {
    "current_people_count": 14
  }
}
```

### 3.2 历史批次接口

接口：

```text
POST /edge/traffic/history-batch
Content-Type: application/json
```

请求体：

```json
{
  "store_id": 1,
  "customer_start_time": "2026-05-18T10:00:00Z",
  "customer_end_time": "2026-05-18T10:01:00Z",
  "customer_enter_total": 3,
  "customer_leave_total": 1
}
```

字段说明：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `store_id` | number | 门店 ID |
| `customer_start_time` | string | 统计窗口开始时间，ISO 8601 / RFC3339 格式 |
| `customer_end_time` | string | 统计窗口结束时间，ISO 8601 / RFC3339 格式 |
| `customer_enter_total` | number | 该窗口内进店人数 |
| `customer_leave_total` | number | 该窗口内出店人数 |

成功响应：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "ai_customer_id": 123
  }
}
```

云端收到后会执行两件事：

1. 写入 Python 数据库的 `ai_customer` 表。
2. 通过 gRPC 调用 Go `StoreBusinessService.PushCustomerFlow`，把 `customer_enter_total` 作为 `in_count` 写入 Go 数据库的 `customer_logs` 表。

## 4. 现有代码限制

当前 `traffic-sense` 的 `TrafficSimulator` 默认只把 `store_id=1` 当作真实边缘数据源：

```text
real_store_ids = {1}
```

因此建议第一轮先用演示门店 `store_id=1` 接入。若后续有多个真实门店，需要在 Aegis 后端扩展真实门店 ID 配置，例如通过环境变量配置：

```text
TRAFFIC_REAL_STORE_IDS=1,2,3
```

否则其他门店可能继续显示后端模拟器数据，而不是 YOLO 上报的真实数据。

另外，当前 `/edge/traffic/*` 接口代码中边缘节点 JWT 鉴权处于注释状态，适合联调。生产环境建议补上专用 Edge Token，例如：

```text
Authorization: Bearer <EDGE_TOKEN>
```

并在服务端校验 token、门店权限、来源 IP 或设备编号。

## 5. YOLO 本地项目实现逻辑

YOLO 项目需要在检测循环里维护四类数据：

| 变量 | 说明 |
| --- | --- |
| `current_people_count` | 当前帧或当前采样时刻画面人数 |
| `enter_total` | 当前统计窗口内累计进店人数 |
| `leave_total` | 当前统计窗口内累计出店人数 |
| `window_start_time` | 当前统计窗口开始时间 |

推荐节奏：

1. YOLO 每帧检测行人。
2. ByteTrack 或其他追踪器维护行人轨迹 ID。
3. 每帧更新 `current_people_count`。
4. 当轨迹跨越门槛线时，根据方向增加 `enter_total` 或 `leave_total`。
5. 每 1 秒调用一次 `/edge/traffic/snapshot`，刷新前端实时人数。
6. 每 1 分钟或每个业务统计窗口调用一次 `/edge/traffic/history-batch`，上传进店/出店累计值。
7. 历史批次发送成功后，重置 `enter_total`、`leave_total` 和 `window_start_time`。
8. 如果网络失败，把待发送数据写入本地 SQLite 或 JSONL 队列，网络恢复后补传。

## 6. YOLO 侧最小 Python 示例

下面代码只展示上报逻辑，不包含 YOLO 推理、ByteTrack 和跨线计数。你可以把 `update_from_yolo()` 替换成自己项目中的检测结果更新逻辑。

```python
import json
import time
from datetime import datetime, timezone
from pathlib import Path

import requests


STORE_ID = 1

# 临时联调：直连 traffic-sense
CLOUD_BASE_URL = "http://<云服务器IP>:8083"

# 正式推荐：走 Nginx/Gateway
# CLOUD_BASE_URL = "http://<域名或云服务器IP>"

SNAPSHOT_URL = f"{CLOUD_BASE_URL}/edge/traffic/snapshot"
HISTORY_BATCH_URL = f"{CLOUD_BASE_URL}/edge/traffic/history-batch"

UNSENT_QUEUE_FILE = Path("unsent_traffic_events.jsonl")


def utc_now_iso() -> str:
    return datetime.now(timezone.utc).isoformat().replace("+00:00", "Z")


def millis_now() -> int:
    return int(time.time() * 1000)


def post_json(url: str, payload: dict, timeout: float = 3.0) -> dict:
    response = requests.post(url, json=payload, timeout=timeout)
    response.raise_for_status()
    data = response.json()
    if data.get("code") != 0:
        raise RuntimeError(f"cloud returned error: {data}")
    return data


def enqueue_unsent(kind: str, payload: dict) -> None:
    record = {
        "kind": kind,
        "payload": payload,
        "queued_at": utc_now_iso(),
    }
    with UNSENT_QUEUE_FILE.open("a", encoding="utf-8") as f:
        f.write(json.dumps(record, ensure_ascii=False) + "\n")


def send_snapshot(current_people_count: int) -> bool:
    payload = {
        "store_id": STORE_ID,
        "current_people_count": max(0, int(current_people_count)),
        "timestamp": millis_now(),
    }
    try:
        post_json(SNAPSHOT_URL, payload)
        return True
    except Exception as exc:
        print(f"[traffic] snapshot send failed: {exc}")
        # 快照是瞬时数据，失败后通常不补传，下一秒会发送新快照。
        return False


def send_history_batch(
    customer_start_time: str,
    customer_end_time: str,
    customer_enter_total: int,
    customer_leave_total: int,
    enqueue_on_fail: bool = True,
) -> bool:
    payload = {
        "store_id": STORE_ID,
        "customer_start_time": customer_start_time,
        "customer_end_time": customer_end_time,
        "customer_enter_total": max(0, int(customer_enter_total)),
        "customer_leave_total": max(0, int(customer_leave_total)),
    }
    try:
        post_json(HISTORY_BATCH_URL, payload)
        return True
    except Exception as exc:
        print(f"[traffic] history batch send failed: {exc}")
        if enqueue_on_fail:
            enqueue_unsent("history_batch", payload)
        return False


def retry_unsent_queue() -> None:
    if not UNSENT_QUEUE_FILE.exists():
        return

    lines = UNSENT_QUEUE_FILE.read_text(encoding="utf-8").splitlines()
    if not lines:
        UNSENT_QUEUE_FILE.unlink(missing_ok=True)
        return

    remaining: list[str] = []
    for line in lines:
        try:
            record = json.loads(line)
            kind = record["kind"]
            payload = record["payload"]

            if kind == "history_batch":
                post_json(HISTORY_BATCH_URL, payload)
            else:
                remaining.append(line)
        except Exception as exc:
            print(f"[traffic] retry failed: {exc}")
            remaining.append(line)

    if remaining:
        UNSENT_QUEUE_FILE.write_text("\n".join(remaining) + "\n", encoding="utf-8")
    else:
        UNSENT_QUEUE_FILE.unlink(missing_ok=True)
```

检测主循环可以按下面的结构改造：

```python
def update_from_yolo() -> tuple[int, int, int]:
    """
    替换成你的 YOLO 项目真实逻辑。

    返回：
    - current_people_count: 当前画面人数
    - enter_delta: 本轮新增进店人数
    - leave_delta: 本轮新增出店人数
    """
    current_people_count = 0
    enter_delta = 0
    leave_delta = 0
    return current_people_count, enter_delta, leave_delta


def reporter_loop() -> None:
    current_people_count = 0
    enter_total = 0
    leave_total = 0

    window_start_time = utc_now_iso()
    last_snapshot_ts = 0.0
    last_batch_ts = time.time()
    last_retry_ts = time.time()

    snapshot_interval_seconds = 1.0
    batch_interval_seconds = 60.0
    retry_interval_seconds = 10.0

    while True:
        # 1. 从 YOLO/追踪器获取最新计数结果
        current_people_count, enter_delta, leave_delta = update_from_yolo()
        enter_total += enter_delta
        leave_total += leave_delta

        now = time.time()

        # 2. 每秒发送当前画面人数，驱动前端实时刷新
        if now - last_snapshot_ts >= snapshot_interval_seconds:
            send_snapshot(current_people_count)
            last_snapshot_ts = now

        # 3. 每个统计窗口发送进店/出店累计值，驱动入库和分析
        if now - last_batch_ts >= batch_interval_seconds:
            window_end_time = utc_now_iso()
            sent = send_history_batch(
                customer_start_time=window_start_time,
                customer_end_time=window_end_time,
                customer_enter_total=enter_total,
                customer_leave_total=leave_total,
            )

            if sent:
                enter_total = 0
                leave_total = 0
                window_start_time = window_end_time

            last_batch_ts = now

        # 4. 定期补传失败的历史批次
        if now - last_retry_ts >= retry_interval_seconds:
            retry_unsent_queue()
            last_retry_ts = now

        time.sleep(0.03)
```

实际接入 YOLO 时，你只需要把原项目里的检测结果映射到：

```python
current_people_count = 当前画面人数
enter_delta = 本帧或本轮新增进店人数
leave_delta = 本帧或本轮新增出店人数
```

然后让 `reporter_loop()` 随 YOLO 主程序启动即可。

## 8. 常见问题

### 8.1 前端仍然显示模拟数据

优先检查：

1. 上报的 `store_id` 是否为 `1`。
2. 当前后端 `TrafficSimulator` 是否只配置了 `real_store_ids={1}`。
3. 前端是否以真实接口模式构建，即 `VITE_USE_MOCK=false`。
4. 浏览器 Network 是否连接到了 `/api/ai/traffic/realtime/1?token=...`。

### 8.2 `history-batch` 返回成功，但 Go 侧没有数据

检查 `traffic-sense` 日志中是否出现：

```text
All StoreBusinessService gRPC addresses failed; customer flow not synced
```

如果出现，说明 `traffic-sense -> store-ops` 的 gRPC 链路失败。Docker 部署下应使用：

```text
GO_STORE_BUSINESS_ADDRS=store-ops:50055
GO_STORE_BUSINESS_ADDR=store-ops:50055
```

本地直跑时才使用：

```text
GO_STORE_BUSINESS_ADDRS=localhost:50055
GO_STORE_BUSINESS_ADDR=localhost:50055
```

### 8.3 时间格式报错

历史批次必须使用 ISO 8601 / RFC3339 时间，例如：

```text
2026-05-18T10:00:00Z
```

不要发送本地中文时间、普通字符串或只有日期的格式。

### 8.4 网络中断是否会丢数据

实时快照是瞬时状态，失败后不建议补传，因为下一秒会有新状态。

历史批次代表统计结果，失败后必须缓存并补传。建议使用 SQLite 或 JSONL 本地队列。本文示例使用 JSONL，便于快速接入；正式边缘节点推荐使用 SQLite，避免断电时文件写入损坏。

## 9. 推荐实施顺序

1. 先用 `curl` 在本地电脑手动调用云端 `snapshot`，确认前端能刷新。
2. 再用 `curl` 调用 `history-batch`，确认云端返回 `ai_customer_id`。
3. 把本文第 6 节的 `send_snapshot()` 和 `send_history_batch()` 复制到 YOLO 项目。
4. 在 YOLO 检测循环中填入真实的 `current_people_count`、`enter_delta`、`leave_delta`。
5. 运行 YOLO 项目，观察前端实时页面。
6. 查看 `traffic-sense` 与 `store-ops` 日志，确认无 gRPC 同步失败。
7. 稳定后再把 `/edge/traffic/*` 从直连 `8083` 改为正式 Nginx/Gateway 入口。
